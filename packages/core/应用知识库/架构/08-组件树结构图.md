    REGISTER1 --> PRESET[预设解析]
    REGISTER2 --> PRESET

    PRESET --> USER[用户插件加载]

### 2. 插件注册流程

```mermaid
sequenceDiagram
    participant Service
    participant PluginAPI
    participant ConfigPlugin
    participant CommonPlugin
    participant HelpPlugin
    participant UserPlugin
    
    Service->>Service: 创建内置插件列表
    
    loop 内置插件初始化
        Service->>PluginAPI: new PluginAPI(id, service)
        Service->>ConfigPlugin: pluginEntry(api, opts, args)
        ConfigPlugin->>PluginAPI: registerSyncAPI('getConfig', fn)
        PluginAPI->>Service: syncMethods['getConfig'] = fn
        
        Service->>CommonPlugin: pluginEntry(api, opts, args)
        CommonPlugin->>PluginAPI: registerSyncAPI('restart', fn)
        PluginAPI->>Service: syncMethods['restart'] = fn
        
        Service->>HelpPlugin: pluginEntry(api, opts, args)
        HelpPlugin->>PluginAPI: registerCommand('help', opts, fn)
        PluginAPI->>Service: commands['help'] = {fn, option}
    end
    
    Service->>Service: resolvePresets(args)
    
    loop 用户插件初始化
        Service->>PluginAPI: new PluginAPI(id, service)
        Service->>UserPlugin: pluginEntry(api, opts, args)
        UserPlugin->>PluginAPI: 注册命令/API
    end
```

## 总结

通过以上组件树结构图，我们可以清晰地看到：

1. **层次化设计**：系统采用清晰的层次结构，从入口模块到具体实现
2. **模块化架构**：每个组件职责明确，耦合度低
3. **插件化扩展**：核心系统通过插件机制实现功能扩展
4. **配置驱动**：多层次的配置系统支持灵活的项目配置
5. **工具支撑**：丰富的工具函数为核心功能提供支持

这种架构设计保证了系统的可维护性、可扩展性和可测试性，为构建复杂的前端工具链提供了坚实的基础。
