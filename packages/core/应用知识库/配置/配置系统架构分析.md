# 配置系统架构分析

## 概述

`@alicloud/console-toolkit-core` 的配置系统采用多层次配置合并策略，支持从多个源加载和合并配置。

## 配置文件查找优先级

### 1. 配置文件名称优先级 (packages/core/src/plugins/config/config.ts:11-16)

```typescript
const CONFIG_FILES = [
  'breezr.config.js',       // 1. 根目录下的 breezr.config.js
  'config/config.js',       // 2. config 目录下的 config.js
  'breezr.config.ts',       // 3. 根目录下的 breezr.config.ts
  'config/config.ts',       // 4. config 目录下的 config.ts
];
```

### 2. 配置文件查找逻辑 (getConfigFile函数)

```typescript
export const getConfigFile = (cwd: string) => {
  const files = CONFIG_FILES.map(file => join(cwd, file)).filter(file =>
    existsSync(file),
  );

  if (files.length > 1) {
    warn(`Multiple config files ${files.join(', ')} detected, breezr will use ${files[0]}.`);
  }
  return files[0];
};
```

## 配置合并策略

### 1. 配置来源层次 (按优先级排序)

1. **用户传入配置** (`opts.config`) - 最高优先级
2. **开发环境配置** (`*.local.js`) - 开发环境专用
3. **配置文件** (`breezr.config.js` 等)
4. **默认配置** (`defaultConfig()`) - 最低优先级

### 2. 配置合并实现 (getConfig API)

```typescript
api.registerSyncAPI('getConfig', () => {
  let devConfig = {};
  if (getEnv().isDev()) {
    try {
      devConfig = require(absConfigPath.replace(/\.js$/, `.local.js`));
    } catch(e) {
      //...
    }
  }

  // 如果用户自己传入了配置, 那么使用传入的配置.
  if (opts.config) {
    config = opts.config;
  }

  if (config) {
    return config;
  }

  config = defaultConfig();
  if (absConfigPath) {
    config = Object.assign(
      {},
      config,
      requireFile(absConfigPath),
      devConfig,
    );
  }

  return config;
});
```

### 3. 默认配置结构 (packages/core/src/plugins/config/options.ts)

```typescript
export const defaultConfig = () => ({
  plugins: [],
  presets: []
});
```

## 配置加载流程

### 1. 文件加载 (requireFile函数)

```typescript
const requireFile = (filePath: string) => {
  if (!existsSync(filePath)) {
    return {};
  }

  try {
    babelRegister([dirname(filePath)]);           // 注册 Babel 转换
    const config = require(filePath) || {};       // 加载配置文件
    return resolveModule(config);                 // 解析模块导出
  } catch (e) {
    console.error(e.stack);
    return {};
  }
};
```

### 2. 配置处理特性

- **TypeScript 支持**: 通过 `babelRegister` 支持 `.ts` 配置文件
- **模块解析**: 使用 `resolveModule` 处理 ES6/CommonJS 模块导出
- **错误处理**: 配置文件加载失败时返回空对象，不中断程序执行
- **调试支持**: 通过 `debug` 模块输出调试信息

## 配置在 Service 中的使用

### 1. 配置获取 (Service.getConfig方法)

```typescript
public getConfig() {
  return this.invokeSync<PluginConfig>('getConfig');
}
```

### 2. 插件配置加载 (Service.loadPluginOptions方法)

```typescript
private loadPluginOptions(id: string) {
  if (id.endsWith('plugins/config/config')) {
    return {
      config: this._serviceOptions.config
    };
  }
  const config = this.getConfig();
  const pluginConfig = config.plugins.find(c => {
    return isArray(c) && c[0] === id;
  });
  // plugin config is [ pluginId, config ]
  return pluginConfig ? pluginConfig[1] : null;
}
```

## 配置系统的工作原理

### 1. 初始化阶段
1. Service 构造函数创建时，配置插件被加载
2. 配置插件注册 `getConfig` 同步API

### 2. 配置解析阶段
1. Service.init() 调用时，首次调用 `getConfig`
2. 配置文件查找和加载
3. 多层配置合并

### 3. 配置使用阶段
1. 插件初始化时获取配置
2. 预设解析时使用配置
3. 命令执行时可访问配置

## 总结

配置系统的核心特性：

1. **多层配置合并**: 支持默认配置、文件配置、开发配置、用户配置的层次合并
2. **文件格式支持**: 支持 `.js` 和 `.ts` 配置文件
3. **灵活的插件配置**: 支持简单字符串和数组形式的插件配置
4. **错误容错**: 配置文件加载失败时不会中断程序执行
5. **调试友好**: 提供详细的调试信息输出

这种设计使得配置系统既灵活又健壮，能够满足不同环境和场景的配置需求。
